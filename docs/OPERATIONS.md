# Operations

## Scripts

All scripts read `.env.local` (via `dotenv`) and are run with `npx tsx scripts/<name>.ts`.

| Script | Reads / writes | Purpose |
|---|---|---|
| `dry-run.ts` | Read-only (Submittable API only; no DB writes) | Preflight check before running the real importer — confirms auth, finds the target project/labels, dumps raw API responses to `fixtures/` so later code is written against real shapes. Safe to run any time. |
| `process-submission.ts` | **Mutating** — Postgres + R2 | The real importer. Pulls submissions from Submittable, renders/classifies/crops pages, uploads images to R2, and writes rows to Postgres. Re-running it for a file that's already been processed **deletes and recreates that file's `ArtAsset` rows** (see Reprocessing below) — it is not purely additive. |
| `tag-all-artwork.ts` | **Mutating** — Postgres (writes `autoGeneratedTags`); calls the Claude API | Quarterly auto-tagging job. Only touches untagged, visible assets — see [`TAGGING.md`](./TAGGING.md) for full detail. |
| `spot-check.ts` | Read-only | Manual QA: prints signed URLs for every hidden asset (to eyeball whether the classifier correctly excluded it) and one sample per known label. |
| `verify-phase2.ts` | Read-only | Manual QA: dumps every submission with its labels, files, and assets, for checking that an import batch landed correctly. |
| `test-db.ts` | Mutating, but self-contained | One-off connectivity check: writes a throwaway row, reads it back, deletes it. Confirms Prisma actually works end-to-end. |
| `test-r2.ts` | Mutating, but self-contained | One-off connectivity check: uploads a tiny object to R2, downloads it, verifies the bytes match, deletes it. |
| `check-counts.ts` (repo root, not `scripts/`) | Read-only | Quick sanity check: prints submission and asset counts. |

### Reprocessing a file (`process-submission.ts`)

Re-running the importer for a `SubmissionFile` that already has assets replaces them: R2 uploads happen first, then a single Postgres transaction deletes the old `ArtAsset` rows for that file and creates the new ones. **This is not atomic across R2 and Postgres** — if the process crashes after uploading to R2 but before the transaction commits, the new objects are orphaned in R2 (no data loss, but some storage waste; nothing in the app currently sweeps orphaned R2 objects). If the transaction itself fails, the old `ArtAsset` rows are untouched (real Postgres transactions roll back) and the file is marked `processingStatus: "error"` for retry.

If the submission's curator-selected thumbnail (`SubmittableSubmission.thumbnailAssetId`) pointed at one of the replaced assets, reprocessing tries to preserve the selection by re-pointing it to the new asset at the same page position. If no asset exists at that position anymore (e.g. the file now has fewer pages), the thumbnail reference is cleared and a warning is logged — the selection is not silently lost, but it does need to be re-picked by a curator.

## Scheduled workflows

Two GitHub Actions cron jobs, both defined in `.github/workflows/`:

| Workflow | Schedule | Purpose |
|---|---|---|
| `tag-artwork.yml` | `0 0 1 1,4,7,10 *` — midnight UTC, 1st of Jan/Apr/Jul/Oct | Runs `tag-all-artwork.ts` against the live DB. |
| `supabase-keepalive.yml` | `0 0 */6 * *` — every 6 days | Runs a single `artAsset.count()` query to prevent Supabase's free-tier database from auto-pausing after 7 days of inactivity. |

**Known gap:** neither workflow notifies anyone on failure beyond GitHub's own UI. The "Notify on failure" step in `tag-artwork.yml` just echoes to the log and exits non-zero — there's no Slack/email hook. If either job silently starts failing (an expired API key, a schema change that breaks the keepalive query), the only way to find out is checking the Actions tab in GitHub. If the tagging job stops running for a full quarter, next quarter's run will simply pick up a larger backlog — nothing is lost, just delayed.

## Troubleshooting

- **Import fails partway through** — `process-submission.ts` marks the specific `SubmissionFile` as `processingStatus: "error"` with the error message in `processingError`; other files in the same run are unaffected. Re-run the script — it only processes files that aren't already `processed`.
- **Tagging fails for one artwork** — see [`TAGGING.md`](./TAGGING.md#failure-modes). It's always safe to just re-run `tag-all-artwork.ts`.
- **Images not loading in the UI** — check that `CLOUDFLARE_R2_*` env vars are correct and that the signed URL hasn't expired (they're generated fresh per request, so this usually points at an R2 credentials or bucket-name problem, not expiry). `test-r2.ts` is the fastest way to confirm R2 connectivity in isolation.
- **DB connection errors** — confirm `DATABASE_URL`/`DIRECT_URL` are current (Supabase connection strings can change if the project is paused and resumed) and that the free-tier project isn't paused. `test-db.ts` isolates this from everything else.
- **Supabase project auto-paused** — free-tier Supabase projects pause after 7 days with no activity. The keepalive workflow exists specifically to prevent this; if it's been disabled or is failing, the project may need to be manually resumed from the Supabase dashboard.

## Environment variables

| Variable | Used by | Notes |
|---|---|---|
| `DATABASE_URL`, `DIRECT_URL` | Prisma (everywhere) | Supabase Postgres connection strings. Rotate from the Supabase dashboard; update both local `.env.local` and the `DATABASE_URL` GitHub Actions secret. |
| `SUBMITTABLE_API_KEY`, `SUBMITTABLE_API_BASE_URL`, `SUBMITTABLE_WEB_BASE_URL` | `src/lib/submittable/client.ts`, importer scripts | Submittable API credentials and endpoints. Only needed for import-related scripts (`dry-run.ts`, `process-submission.ts`) — not needed to run the app itself day-to-day. |
| `ANTHROPIC_API_KEY` | `tag-all-artwork.ts` | Claude API key. Only needed to run the tagging job (locally, or as the `ANTHROPIC_API_KEY` GitHub Actions secret for the scheduled workflow). |
| `CLOUDFLARE_R2_ENDPOINT`, `CLOUDFLARE_R2_ACCESS_KEY_ID`, `CLOUDFLARE_R2_SECRET_ACCESS_KEY`, `CLOUDFLARE_R2_BUCKET` | `src/lib/storage/r2.ts` | R2 credentials for reading/writing rendered images. Rotate from the Cloudflare dashboard. |
| `APP_PASSWORD` | `src/lib/auth.ts` | Single shared login password for the app. Rotating it logs out every active session (the cookie is checked against the current value on each request). |
| `ART_LIBRARY_EXPECTED_SUBMISSION_COUNT`, `ART_LIBRARY_PROJECT_NAME`, `ART_LIBRARY_REQUIRED_LABEL`, `ART_LIBRARY_REQUIRED_STATUS` | Importer scripts | Sanity-check/filter config used to confirm the importer is pointed at the right Submittable project and pulling the right subset of submissions. |

None of these are needed to just browse the already-imported library locally except `DATABASE_URL`/`DIRECT_URL`, the R2 credentials, and `APP_PASSWORD` — Submittable and Anthropic credentials are only exercised by the import and tagging scripts respectively.
