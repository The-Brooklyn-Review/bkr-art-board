# Auto-tagging

`scripts/tag-all-artwork.ts` generates searchable tags for artwork using the Claude API: visual analysis of the image, plus theme extraction from the artist's statement.

## When it runs

- **Automatically**, every 3 months (`.github/workflows/tag-artwork.yml`, cron `0 0 1 1,4,7,10 *` — midnight UTC on Jan/Apr/Jul/Oct 1).
- **Manually**, any time:

  ```bash
  npx tsx scripts/tag-all-artwork.ts
  ```

  Add `--test` to process only the first 3 eligible assets — useful for checking that a prompt or model change still parses correctly before running it against the whole library.

## What it processes

Only `ArtAsset` rows where `visibleInArtLibrary: true` and `autoGeneratedTags: null`. This means:

- Hidden assets (cover letters, CVs — anything `classifyPage()` decided wasn't artwork) are never tagged.
- Already-tagged assets are never re-processed or re-billed, even on a re-run.
- **Failed assets stay eligible for retry.** If a run fails partway through an asset (a fetch error, a malformed model response), that asset's `autoGeneratedTags` is never written, so it's picked up again on the next run — scheduled or manual — with no special retry logic needed.

## How it works

Two separate Claude API calls per artwork rather than one combined call:

1. **Vision-only** — the image, no text context. Extracts concrete visual elements (medium, subject, composition, style) and interpretive ones (mood, aesthetic themes), plus dominant colors.
2. **Text-only** — the artist's statement (first 1,500 characters), no image. Extracts conceptual themes and intent.

The split exists because a single combined call was prone to truncation and JSON parse failures on longer statements — splitting took success across the full library from ~91% to 100%. Results are merged into one `combined`, deduplicated, sorted tag list and written to `ArtAsset.autoGeneratedTags` as a JSON string (see `AutoGeneratedTags` / `parseAutoGeneratedTags` in [`src/lib/art-library/getAssets.ts`](../src/lib/art-library/getAssets.ts) for how it's read back).

## Model

Both calls use `claude-sonnet-4-6`. Sonnet-tier is intentional here — this is a batch classification/extraction job with a fixed structured-JSON output, not something that needs frontier reasoning, and running it at Opus prices against hundreds of artworks would be wasteful. If you touch this script, keep the model ID current — check it against the latest model catalog rather than assuming the string is still valid, since Anthropic periodically retires older model versions.

## Cost

Estimated **$0.02–0.04 per artwork** (two Sonnet-tier calls: an image + short prompt, then a short text prompt). Tagging the initial 207-artwork library cost about $4. At an estimated 100–200 new submissions per year, budget roughly **$6/year**. These are rough estimates from actual runs, not a contract — Anthropic's pricing can change, and actual cost scales with image size and statement length. The script prints actual token usage and an estimated cost at the end of every run.

## Data usage

Per Anthropic's standard commercial API terms, inputs and outputs sent through the API are not used to train Anthropic's models. This script sends artwork images and artist statements to the API for analysis only. If this matters for a specific compliance need, verify current terms directly with Anthropic rather than relying on this note, since usage policies can change.

## Failure modes

- **A single asset fails** (image fetch error, malformed JSON in the model's response): the script logs it, moves on, and leaves that asset untagged for the next run to pick up.
- **The whole run fails** (bad `ANTHROPIC_API_KEY`, DB connection lost): the GitHub Actions job fails and is visible in the Actions tab; nothing partial is left in a bad state, since each asset's tag write is independent and only committed after both calls succeed and parse.
